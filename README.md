# 玄武 WL-X｜轮腿式无人作战平台

> **复杂系统工程课程作业集成网页**  
> 以同一概念平台为对象，展示“系统由什么构成”与“为什么需要、谁需要、需要达到什么”的两次递进分析。

## 一、项目简介

**玄武 WL-X（XUANWU / WL-X）** 是面向复杂地形前沿侦察和伴随支援任务提出的**轮腿式无人平台概念方案**。网页以四轮腿独立驱动平台为研究对象，围绕任务、体系协同、整机选型、功能架构和需求定义，整合两次系统工程课程作业。

本项目的主要目标是运用系统工程方法组织、分解与追溯设计信息，并以交互式网页清晰呈现分析成果，而非提供实际装备的制造方案。

> **说明：** 网页内的平台参数、任务指标及需求阈值均为课程概念设计目标，**不代表已通过实物试验验证的性能**。高风险行为受人工授权与安全约束，平台不自主决定对人员施加致命效应。

## 三、作业 01：系统六级分解

按照 **任务 → 体系 → 整机 → 系统 → 子系统 → 模块** 的六级路径，自上而下完成系统分析。

### 1. 任务（Mission）

平台主要任务为**复杂地形前沿侦察与持续警戒**，扩展任务包括通信中继、物资伴随、危险区探测及伤员后送。网页展示从任务受领、自主机动、多源感知、边缘融合、人工确认到共享态势的任务闭环。

### 2. 体系（System of Systems）

分析 WL-X 与六类外部系统的协同关系：战术指挥控制、有人作战分队、无人机侦察、通信导航、效应与火力、保障训练，并区分数据、控制、物理和保障接口。

### 3. 整机（Vehicle）

对比五类候选构型：两轮平衡腿式、四轮腿独立驱动、六轮腿重载式、轮腿变形式和轮足/被动轮式。通过加权选型矩阵，最终选定**四轮腿独立驱动**概念方案，矩阵加权总分为 **4.25 / 5**。

网页采用的整机概念基线如下（均为课程目标值）：

| 指标 | 概念值 |
| --- | --- |
| 战斗全重 | ≤ 2.4 t |
| 道路速度 | 45 km/h |
| 持续任务 | 8 h |
| 有效载荷 | 350 kg |
| 垂直越障 | 0.6 m |
| 涉水深度 | 0.8 m |

### 4—6. 系统、子系统与模块

在整机方案基础上进行逐级分解：

- **10 个一级系统**：覆盖任务能力、平台基础及安全保障。
- **50 个子系统**：落实各一级系统的功能职责及边界。
- **203 个末端模块**：构成可进一步设计、采购、试验与替换的分解单元。

网页支持按系统切换子系统、按关键词检索模块，以及按任务能力/平台基础/安全保障筛选模块。六级追溯示例展示了模块与上层任务之间的关联关系。

## 四、作业 02：需求分析与定义

围绕 **BMA → BRS → ConOps → OpsCon → Stakeholders → StRS** 建立从任务问题到可验证相关方需求的分析链条。

| 阶段 | 名称 | 主要内容 |
| --- | --- | --- |
| BMA | 业务/任务分析 | 问题与机会、战略意图、候选方案、成功判据（MOE） |
| BRS | 业务需求规格 | 业务目标、运行需求、约束、生命周期概念和需求基线 |
| ConOps | 运营概念 | 组织与体系层的任务阶段、多组织协同、正常及偏离场景 |
| OpsCon | 运行概念 | WL-X 关注系统的边界、外部接口、运行模式及人机职责 |
| Stakeholders | 相关方识别 | 相关方角色、影响力、参与方式与需求获取 |
| StRS | 相关方需求规格 | 可验证需求、优先级、验证方法及双向追溯 |

### 业务/任务目标

网页设定人员暴露降低、任务完成率、态势时效、复杂地形覆盖、持续任务及安全事件等六项 **MOE（有效性度量）**，作为概念阶段的成功判据。

### BRS 与 StRS

BRS 根据课程指定资料组织为八章内容，描述组织/业务层的需求和项目约束；StRS 同样采用八章结构，将相关方期望整理为**30 条相关方需求**，并记录来源、优先级、验证方法和追溯关系。

网页重点区分：

- **ConOps**：关注多个组织和系统如何协同达成整体任务效果。
- **OpsCon**：聚焦 WL-X 单一关注系统如何被使用、监督、保障，以及在异常情况下如何降级或退出。

需求质量检查强调完整、一致、单一、清晰、可行、可验证、设计无关和可追溯。

## 五、网页设计与交互特色

1. **统一的项目入口**：首页集中展示两次作业，可快速切换。
2. **分阶段导航**：两套六步骤侧边导航与内容章节一一对应。
3. **图表化表达**：使用平台概念示意图、体系关系图、选型矩阵、任务流程和运行模式图等组织信息。
4. **交互式分解浏览**：通过系统标签切换子系统，并对 203 个末端模块进行搜索和分类筛选。
5. **需求查询**：展示 BRS 和 StRS 需求表，并提供相关方需求检索与分类筛选入口。
6. **答辩模式**：顶部设置“答辩模式”按钮，便于课堂展示。
7. **参考资料**：为两次作业分别设置参考文献部分，说明课程资料、系统工程标准与研究文献依据。

## 七、项目总结

本网页以 WL-X 概念平台为统一案例，把**系统六级分解**和**需求分析与定义**组织在同一展示框架下。作业 01 说明系统从任务到末端模块的组成关系；作业 02 解释业务目标、运行场景、相关方诉求及可验证需求的来源与联系。
